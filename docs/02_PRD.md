# 会议录音转写与会议纪要生成工具 - PRD

## 1. 产品目标

这个工具要解决的问题是：用户有一段较长的会议录音，但不想花大量时间手动听录音、打字、整理会议纪要。

第一版系统以本地网页工具形式运行，用户在本机浏览器打开页面使用。数据默认保存在本机，不做云端账号系统。

产品希望做到：

- 用户上传会议录音。
- 系统把录音自动转成文字。
- 系统用“发言人1、发言人2”这样的方式区分不同说话人。
- 用户可以修改转写出来的文字。
- 系统根据转写文字生成会议纪要和报告提纲，用户也可以修改这些内容。
- 用户可以在页面查看、复制、导出结果。
- 系统把历史记录自动保存在本机，方便以后查看。
- 用户也可以点击“保存到本机”进行手动立即保存。
- 用户可以删除单条历史记录，删除前需要二次确认。

第一版的核心目标是先把“上传录音到拿到会议纪要”的完整流程跑通。

## 2. 用户流程

用户使用流程如下：

1. 用户打开系统页面。
2. 用户上传一段会议录音。
3. 系统显示处理状态，让用户知道正在转写或生成内容。
4. 系统展示转写文本，并用“发言人1、发言人2”区分不同说话人。
5. 用户可以在页面上修改转写文字。
6. 系统根据转写文字生成会议纪要。
7. 系统根据转写文字生成报告提纲。
8. 用户可以修改转写文字、会议纪要和报告提纲。
9. 用户可以复制转写文字、会议纪要或报告提纲。
10. 用户可以导出 Word 或 PDF。
11. 系统在关键操作后自动保存当前会议记录。
12. 用户也可以点击“保存到本机”进行手动立即保存。
13. 用户以后可以从历史记录里重新打开之前的会议内容。
14. 用户可以删除不需要的单条历史记录，删除前需要二次确认。

## 3. 功能优先级

### MVP 0：假数据 UI 原型

MVP 0 的目标是先确认页面长什么样、用户流程顺不顺，不接真实 API，也不真正处理录音。

必须包含：

- 上传音频区域。
- 转写文本展示区域。
- 转写文本可编辑。
- 会议纪要展示区域。
- 报告提纲展示区域。
- 历史记录展示区域。
- 复制按钮。
- Word/PDF 导出按钮先做成占位按钮。

MVP 0 可以使用假数据。例如用户点击上传后，页面直接显示一段示例转写文字、示例会议纪要和示例报告提纲。这样可以先让客户确认页面流程和内容结构。

### MVP 1A：真实核心流程

MVP 1A 的目标是跑通真实业务闭环，让客户可以上传真实录音，并拿到真实生成的转写文字、会议纪要和报告提纲。

包含：

- 上传真实音频。
- 调用外部转写 API。
- 支持中文普通话。
- 支持发言人编号区分，如“发言人1、发言人2”。
- 用户可以修改转写文字。
- 用户可以修改会议纪要。
- 用户可以修改报告提纲。
- 调用大模型生成会议纪要和报告提纲。
- 历史记录保存在本机并长期保留。
- 支持自动保存历史记录。
- 自动保存触发时机包括：上传录音、转写完成、生成纪要、编辑转写文本、编辑会议纪要、编辑报告提纲。
- 自动保存时显示“正在保存...”。
- 自动保存成功显示“已自动保存”。
- 自动保存失败显示“自动保存失败，请点击手动保存”。
- “保存到本机”按钮保留，作为手动立即保存按钮。
- 支持删除单条历史记录，删除前需要二次确认。
- 支持复制转写文字、会议纪要和报告提纲。

MVP 1A 做完后，应该可以拿一段真实中文会议录音进行演示，并完整展示从上传、转写、编辑、生成纪要、生成提纲、保存历史到复制结果的流程。

### MVP 1B：导出增强

MVP 1B 的目标是在真实核心流程已经跑通后，补上 Word 和 PDF 导出能力。

包含：

- 支持导出 Word。
- 支持导出 PDF。
- 不需要公司固定模板，使用通用排版即可。

MVP 1B 做完后，用户不仅可以在页面查看和复制结果，还可以把结果导出成常见文件，方便发送、存档或打印。

### P1：后续增强

这些功能有价值，但不建议放进第一版核心范围：

- 自定义会议纪要模板。
- 更好看的 Word/PDF 排版。
- 搜索历史记录。
- 批量删除历史记录。

批量删除暂不进入 MVP 1A。原因是当前第一版是单人本机使用，批量删除不是“上传录音到生成纪要”的核心闭环，先不扩大第一版范围。

### P2：以后再说

这些功能复杂度更高，或者当前客户已经确认第一版暂时不需要：

- 多人权限管理。
- 账号登录。
- 手机 App。
- 接入会议软件。
- 自动识别真实姓名。
- 完全离线部署。

## 4. 第一版暂时不做什么

第一版为了尽快验证核心流程，明确暂时不做以下内容：

- 不做登录。
- 不做多人权限。
- 不做手机 App。
- 不做真实姓名识别，只显示“发言人1、发言人2”。
- 不做公司固定模板，Word/PDF 使用通用格式即可。
- 不做完全离线，系统可以联网调用外部 API。

## 5. 验收标准

### MVP 0 验收标准

MVP 0 完成的标准是：

- 页面上能看到上传音频区域。
- 页面上能看到转写文本区域。
- 转写文本可以被用户手动修改。
- 页面上能看到会议纪要区域。
- 页面上能看到报告提纲区域。
- 页面上能看到历史记录区域。
- 页面上有复制按钮。
- 页面上有 Word/PDF 导出按钮，按钮可以先不真正导出，但要让客户看到位置和流程。
- 使用假数据也能完整演示一次页面流程。
- 客户看完后能判断页面布局、操作流程和内容结构是否符合预期。

### MVP 1A 验收标准

MVP 1A 完成的标准是：

- 用户可以上传一段真实中文普通话会议录音。
- 系统可以调用外部转写 API，把录音转成文字。
- 转写结果可以用“发言人1、发言人2”区分不同说话人。
- 用户可以在页面上修改转写文字。
- 系统可以调用大模型生成会议纪要。
- 系统可以调用大模型生成报告提纲。
- 用户可以在页面上修改会议纪要。
- 用户可以在页面上修改报告提纲。
- 用户可以复制转写文字、会议纪要或报告提纲。
- 历史记录可以保存在本机。
- 上传录音后，系统可以自动保存当前会议记录。
- 转写完成后，系统可以自动保存转写结果。
- 生成会议纪要和报告提纲后，系统可以自动保存生成结果。
- 用户编辑转写文本、会议纪要或报告提纲后，系统可以自动保存修改后的内容。
- 自动保存时页面显示“正在保存...”，成功后显示“已自动保存”。
- 如果自动保存失败，页面显示“自动保存失败，请点击手动保存”。
- 用户可以点击“保存到本机”进行手动立即保存。
- 用户可以删除单条历史记录，删除前有二次确认。
- 删除后，该记录从左侧历史记录中移除。
- 关闭系统后再次打开，之前的历史记录仍然存在。
- 可以用一段真实会议录音完整演示从上传到复制结果的流程。

### MVP 1B 验收标准

MVP 1B 完成的标准是：

- 用户可以导出 Word 文件。
- 用户可以导出 PDF 文件。
- Word/PDF 不需要公司固定模板，但内容应包含转写文字、会议纪要和报告提纲。
- 导出的文件内容和页面上用户最终修改后的内容一致。
- 可以在 MVP 1A 的真实流程基础上，完整演示从上传到导出文件的流程。
