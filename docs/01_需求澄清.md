# 会议录音转写与会议纪要生成工具 - 需求澄清

## 1. 项目要解决的问题

很多会议都会产生较长的录音，但会后人工整理文字记录和会议纪要很耗时，也容易漏掉重点。这个项目希望帮助用户把会议录音自动转成文字，并进一步生成清晰的会议纪要，让用户能快速回看会议内容、复制重点、导出文件，并保存历史记录，方便以后查找。

## 2. 目标用户

第一版主要面向需要经常开会、整理会议内容的人，例如：

- 公司管理者、项目经理、行政人员
- 销售、客户成功、咨询顾问
- 需要记录访谈、讨论、培训内容的团队成员
- 不懂技术、只希望“上传录音，然后拿到结果”的普通用户

## 3. 用户使用流程

用户理想中的使用方式可以理解为：

1. 打开系统页面。
2. 上传一段会议录音。
3. 系统自动识别录音内容，把语音转成文字。
4. 系统尽量区分不同发言人，例如“发言人1”“发言人2”。
5. 系统根据转写内容生成会议纪要。
6. 用户在页面上查看结果，并且可以修改转写文字。
7. 用户可以复制文字，也可以导出 Word 或 PDF。
8. 系统把历史记录保存在本机，用户下次进入系统时可以继续查看。

## 4. 当前已确认需求

客户已经确认以下内容：

- 系统可以联网调用外部 API。
- 客户电脑或服务器的系统和配置暂不清楚，但客户认为应该够用。
- 录音主要是中文普通话。
- 单个录音一般在 30 分钟以上。
- 需要区分不同发言人，显示为“发言人1、发言人2”即可，不需要自动识别真实姓名。
- 最终结果希望支持页面展示、复制、Word、PDF。
- 需要保存历史记录。
- 第一版是单人使用。
- 暂时不需要账号登录。
- 历史记录直接保存在本机，并且默认长期保存。
- 用户需要可以在页面上修改转写文字。
- Word/PDF 不需要公司固定模板。
- 外部转写 API 和大模型账号/模型由我们这边选型和接入。

## 5. 当前仍不确定的问题

目前还有一些关键问题没有确定，这些问题会影响后续产品设计、技术选型和开发成本：

- 录音文件常见格式是什么，例如 mp3、wav、m4a、mp4？
- 单个录音最长可能多长？文件最大可能多大？
- 对转写准确率的要求有多高？
- 会议纪要需要什么格式，例如摘要、待办事项、决策结论、风险问题、完整逐字稿？
- Word 和 PDF 是否需要更美观的通用排版？
- 外部 API 是否有预算限制？
- 录音内容是否涉及敏感信息？是否有隐私、安全或合规要求？
- 系统运行在客户本地电脑，还是客户自己的服务器？
- 用户是否需要编辑会议纪要，还是只编辑转写文字即可？

## 6. 第一版建议先做什么

第一版建议先做一个“能跑通完整流程”的版本，重点验证核心价值：

- 支持上传常见音频文件。
- 支持中文普通话转写。
- 支持长录音处理。
- 支持基础的发言人区分。
- 支持自动生成一份结构清楚的会议纪要。
- 支持在页面查看转写文本和会议纪要。
- 支持用户修改转写文字。
- 支持一键复制结果。
- 支持导出 Word 和 PDF。
- 支持在本机长期保存并查看历史记录。

第一版的目标不是做到所有细节完美，而是先让用户真实完成一次从“上传录音”到“拿到会议纪要”的完整体验。

## 7. 第一版暂时不做什么

为了降低第一版复杂度，建议暂时不做以下内容：

- 暂时不做复杂的多人权限管理。
- 暂时不做账号登录。
- 暂时不做大型企业级审批流程。
- 暂时不做非常精细的会议模板管理。
- 暂时不保证每个发言人都能自动识别成真实姓名。
- 暂时不做手机 App。
- 暂时不做离线语音识别。
- 暂时不做复杂的数据统计和报表。
- 暂时不接入多个不同会议软件。

这些功能可以等第一版验证通过后，再根据客户真实使用反馈逐步增加。

## 8. 需要继续问客户的问题

下一步建议继续向客户确认这些问题：

1. 录音文件一般来自哪里？手机录音、会议软件录音，还是其他设备？
2. 常见录音格式有哪些？
3. 单个录音最长大概多久？文件最大大概多大？
4. 是否需要上传视频文件并提取其中的音频？
5. 会议纪要希望包含哪些固定栏目？
6. 用户是否也需要在页面上修改会议纪要？
7. Word 和 PDF 是否需要更美观的通用排版？
8. 录音内容是否包含客户隐私、商业秘密或个人敏感信息？
9. 客户更希望系统运行在本地电脑，还是自己的服务器？
10. 客户对处理速度有什么预期，例如 30 分钟录音希望多久出结果？
11. 外部 API 是否有费用预算或供应商偏好？
